# エラー係のチャット

アプリで起きたエラー（日記の添削ができなかった、音声を作れなかった、サーバーや画面のエラー）は、アプリのデータベースに記録される（`lessons/src/errors.js`）. 先生は Claude のチャットを1つ「エラー係」にしておく. エラー係は、1時間に1回、新しいエラーがないかを見て、直せるものはその場で直し、先生に知らせる.

先生がこのチャットに「〇〇さんの画面がおかしい」のように書いて、調べてもらうこともできる.

はじめの設定は、生徒ごとのチャットと同じ（`docs/student-chats.md` の「はじめに」. `HINA_TEACHER_TOKEN` とネットワーク）.

## 記録されるもの

| 種類 | いつ | 生徒の画面では |
| --- | --- | --- |
| 日記の添削 | AI の添削が失敗した（Anthropic のエラー、混雑、クレジット切れ など）. または、送って 10 分たっても、添削も失敗の記録もない日記（送ったあと、途中で止まった） | 「もう一度ためす」ボタンが出る |
| AI の判定 | 打った答えの AI 判定が失敗した | 教材の答えで判定される |
| 音声 | 🔊 の音声を作れなかった | スマホの声で読む |
| サーバー | サーバーの思わぬエラー（コードのバグなど） | 「サーバーでエラーが起きました」 |
| 画面 | 生徒の画面か先生ページで、スクリプトのエラー（ブラウザから送られる. 1 ページ 5 件まで） | いろいろ |

- 同じエラーが、まだ直っていないうちにまた起きたときは、新しい行は作らず回数が増える
- 日記の添削は、あとで添削できたら（生徒の「もう一度ためす」でも、エラー係の `retry-journal` でも）、自動で「直した」になる
- 「くわしく」（`|` の行）に、本当の原因（Anthropic の API のステータスとメッセージ、スタック、ページ、ブラウザ）が出る
- 直したものは 90 日で消える

## コマンド

```sh
cd lessons
node scripts/teacher.mjs errors                  # まだ直っていないエラー. 前に見たあとに起きたものに「新」. 見ると「新」は消える
node scripts/teacher.mjs errors --peek           # 見るだけ（「新」を消さない）
node scripts/teacher.mjs errors --all            # 直したものもふくめて、新しい順に 100 件
node scripts/teacher.mjs retry-journal 225       # 日記 225 を、AI にもう一度添削してもらう（添削がない日記だけ）
node scripts/teacher.mjs error-done 12 "どう直したか"   # エラー 12 を「直した」にする
```

番号は `[12]` がエラーの番号、「日記 225」が日記の番号.

## 1時間ごとの確認

1. `errors` を実行する
2. 「新」がなければ、「新しいエラーなし」と1行だけ返して終わる（ほかのことはしない）
3. 「新」があれば、種類ごとに：
   - **日記の添削**：`retry-journal 日記の番号`. 添削できたら終わり（エラーは自動で閉じる）. また失敗したら「くわしく」を見る
     - `401`・authentication → `ANTHROPIC_API_KEY` がまちがっている・消えた. 先生に知らせる（キーは先生が Cloudflare の Worker の Variables and Secrets に入れる）
     - `400` で credit balance → Anthropic のクレジット切れ. 先生に知らせる（console.anthropic.com の Billing）
     - `429`・`529`・overloaded・`500` → 一時的. 次の確認でもう一度 `retry-journal`. 3 回続けて失敗したら先生に知らせる
     - refusal → 内容で断られた. 先生に知らせる（生徒に文章を少し変えてもらう）
   - **AI の判定**：一時的なことが多い. 同じ時間に日記の添削も失敗していたら、上と同じ見方（キー・クレジット）. 1 回だけなら `error-done`
   - **音声**：一時的なことが多い（その日の無料枠を使いきった、Workers AI の不調）. 生徒はスマホの声で聞けている. 半日以上続くときだけ先生に知らせる. 次の日に起きていなければ `error-done`
   - **サーバー・画面**：コードのバグのことが多い. 「くわしく」（スタック、ページ、ブラウザ）から、リポジトリのコード（`lessons/`）を読んで原因を探す. 直せるときは、原因と直し方を先生に短く説明して OK をもらってから、ブランチで直して push し、「PR を開きますか？」と聞く（先生がマージすると Cloudflare に出る）. 出たあとに `error-done 番号 "どう直したか"`
4. 先生への報告は短く：何が起きたか（生徒・時間）、直したか、先生にしてほしいこと
5. 先生がすることがあるとき（キー・クレジット・PR など）は、PushNotification のツールが使えれば、それでも知らせる

直るまで待つもの（クレジットが入るのを待つ など）は、開いたままにしておく. 「新」でなければ、1時間ごとの確認では何もしない. 直さないと決めたもの（1 回だけの一時的なエラーなど）は、理由をつけて `error-done` で閉じる.

## 決まり

- リポジトリは公開されているので、生徒の日記の本文やエラーの中身を、リポジトリのファイルに書かない. 一時ファイルはリポジトリの外（/tmp など）に置く
- 環境変数 `HINA_TEACHER_TOKEN` の値は、表示・出力・コピーしない
- 生徒の内容（単語・授業メモ・発音など）は変えない. それは生徒ごとのチャットの仕事
- アプリのコードを変えるのは、先生の OK のあとだけ. PR は先生が「PR開いて」と言ったときだけ. マージは先生がする
- 生徒の日記を AI に送り直すのは `retry-journal` だけ. 添削のある日記を消したり、書きかえたりしない
